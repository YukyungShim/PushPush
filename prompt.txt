본 문서는 '푸시푸시(소코반)'의 기본 규칙에 '무중력(Anti-gravity)' 기믹을 결합한 웹 기반 퍼즐 게임의 기획, Vercel 배포, Supabase 연동 및 프롬프트 엔지니어링을 통한 스테이지 생성 전략을 정의합니다.

---

## 1. 게임 코어 메커니즘: Anti-Gravity (무중력) 기믹 정의
*   **방향 A (마찰력 제로 / 관성 이동):** 플레이어가 공을 밀면, 공이 한 칸만 이동하는 것이 아니라 **벽이나 다른 장애물에 부딪힐 때까지 멈추지 않고 미끄러집니다.** (Ice Sliding 기믹)

> **설계 권장:** 퍼즐의 직관성과 난이도 조절 측면에서는 **방향 A(관성 이동)**가 모바일/웹 환경에서 더 적합하며, 스테이지 확장이 용이합니다.


## 2. 시스템 아키텍처 및 Supabase 연동 구조

Vercel과 Supabase를 활용한 서버리스(Serverless) 아키텍처로 구성하여 유지보수 비용을 최소화하고 성능을 극대화합니다.

### 2.1. 기술 스택
*   **Frontend / Game Client:** Next.js (React) 기반. 게임 보드는 HTML Canvas API 또는 단순 CSS Grid 배열로 구현.
*   **Backend / DB:** Supabase (PostgreSQL, Row Level Security 활용).
*   **Hosting:** Vercel (정적 에셋 캐싱 및 Edge Functions 활용).

### 2.2. Supabase DB 스키마 설계 (리더보드용)
경쟁 요소를 극대화하기 위해 최소 이동 횟수(Moves)와 클리어 시간(Time)을 기록합니다.


## 3. 거듭되는 스테이지(난이도 우상향) 생성을 위한 AI 프롬프트 가이드

LLM(대규모 언어 모델)이나 자동화 스크립트를 통해 스테이지를 생성할 때, 단순 무작위 배치가 아닌 **정밀한 난이도 상향 곡선(Difficulty Curve)**을 그리도록 지시해야 합니다. 

아래는 AI에게 스테이지 디자인을 요청할 때 사용할 수 있는 **구조화된 지시문(Prompt) 템플릿**과 **난이도별 제약 조건**입니다.

### 3.1. 기본 지시문 (System Prompt)
> "당신은 전문 퍼즐 게임 레벨 디자이너입니다. '무중력 관성 이동(밀면 벽에 닿을 때까지 미끄러짐)' 규칙이 적용된 2D 그리드 기반의 소코반 맵을 생성해야 합니다. 
> 맵의 기호는 다음과 같습니다. 
> `.`(빈 공간), `#`(벽), `O`(공), `X`(목적지), `@`(플레이어), `*`(목적지 위의 공)
> 맵은 반드시 테두리가 벽(`#`)으로 닫혀 있어야 하며, 100% 클리어 가능해야 합니다."

### 3.2. 난이도별 세부 지시 조건 (Phase 제어)

AI에게 스테이지 생성을 요청할 때, 아래의 '제한 조건'을 단계별로 추가하여 난이도를 우상향시킵니다.

#### Phase 1: 튜토리얼 (Stage 1 ~ 5)
*   **목적:** 사용자가 관성 이동 규칙을 체감하도록 유도.
*   **프롬프트 추가 조건:** "공의 개수는 1개로 제한합니다. 맵 크기는 5x5 이하로 설정하세요. 공이 한 번 벽에 튕긴 후 목적지에 도달할 수 있는 '1쿠션' 구조로 설계하십시오."

#### Phase 2: 초/중급 (Stage 6 ~ 15)
*   **목적:** 장애물(벽)을 활용한 정지 위치 계산 요구.
*   **프롬프트 추가 조건:** "공의 개수는 2~3개로 설정하고, 맵 크기는 7x7로 확장하세요. 목적지는 맵의 중앙 빈 공간에 위치해야 하며, 공이 목적지에 서기 위해서는 **다른 공을 먼저 특정 위치에 배치하여 '임시 벽'으로 활용해야만** 하는 로직을 반드시 포함시키세요."

#### Phase 3: 고급 (Stage 16 ~ 30)
*   **목적:** 다단계 연쇄 반응 및 데드록(Deadlock) 회피 설계.
*   **프롬프트 추가 조건:** "맵 크기를 10x10으로 설정하세요. 최소 이동 횟수(Optimal moves)가 15회 이상이 되는 구조여야 합니다. 좁은 통로(폭 1칸)와 넓은 공간(3x3)을 교차로 배치하여, 순서를 잘못 맞추면 데드록이 발생하는 함정(Trap) 구역을 2곳 이상 포함시키세요."

### 3.3. 레벨 유효성 검증 로직 (개발자 체크리스트)
AI가 생성한 텍스트 맵을 Vercel에 배포하기 전, 코드로 검증해야 할 요소입니다.
1.  `count(O) == count(X)` 일치 여부 확인.
2.  BFS/DFS 기반의 최단 거리 탐색 알고리즘을 돌려 **클리어까지의 최소 이동 횟수(Moves)** 산출.
3.  이동 횟수가 이전 스테이지보다 높거나, 교차점 방문 횟수가 많을 경우에만 다음 스테이지로 확정(난이도 우상향 보장).
